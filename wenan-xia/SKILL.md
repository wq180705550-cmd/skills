# 文案虾 (Copywriting Shrimp)

## Overview

文案虾是「选题虾」内容生产流水线的**下游环节**，专职把选题卡 / 思路变成可直接发布的成品。
它产出**最终文案**，并负责多平台适配、去 AI 味、归档与索引。

**核心要求（来自用户）**：
- 符合用户风格
- 去 AI 味
- **直接给结果**（不绕弯子，不回"以下是为您生成的……"这类客套）

结构化风格规范见 `references/style-guide.md`，去 AI 味手法见
`references/humanize-guide.md`，确定性归档由 `scripts/archive_content.py` 完成。

---

## 职责：成文 + 改写流水线

```
选题卡 / 思路
   │
   ├─① 大纲生成  ──→ 结构化大纲（骨架+要点，不写正文）
   ├─② 初稿写作  ──→ 按大纲+风格规则写初稿
   ├─③ 润色优化  ──→ 去 AI 味（Humanizer 优先，否则按指南兜底）
   ├─④ 多平台改写 ──→ 公众号 / 小红书 / 知乎 / 今日头条 ...
   └─⑤ 索引生成  ──→ 归档成品 + 内容索引 + 版本管理
```

五个步骤顺序执行；③④ 可针对同一初稿多次运行以产出不同平台版本。

---

## 五大核心能力（工作流）

### 1. 大纲生成

**双路策略**（与「选题虾」的 tencent-news 兜底一致）：
1. **优先**：若 WorkBuddy 环境内置「内容创作专家」可用，调用它生成结构化大纲。
2. **兜底**：若不可用，由本技能按 `references/style-guide.md` 第二节「大纲结构模板」
   直接生成（LLM 执行），效果等价。

> 判断方式：尝试一次轻量「内容创作专家」调用；捕获「工具不存在 / 未授权」等错误时，
> 立即切换兜底路径，并说明"已用内置大纲模板生成"。

大纲统一落为：标题（钩子型）→ 核心立论 → 开篇（≤3句）→ 主体（2–4 分论点）→ 结尾（金句/行动召唤）。
**大纲只列骨架与每节要点/素材方向，不写正文。**

### 2. 初稿写作

按大纲 + `references/style-guide.md` 第一节「核心风格规则」生成初稿：
- 开篇 ≤3 句直接切入，无铺垫。
- 短句为主、长短交错；去套话；具体不抽象。
- 若输入来自「选题虾」选题卡，把 `core_points` 直接映射到主体分论点，`tone` 决定风格强度，`emos_hit` 提示在哪些维度（情绪/动机/观点/社交）加力。

### 3. 润色优化（去 AI 味）

**双路策略**：
1. **优先**：若 `Humanizer` 工具/技能可用，调用它去除 AI 痕迹。
2. **兜底**：若不可用，由 LLM 严格按 `references/humanize-guide.md` 一~三节
   （词汇层 / 句式层 / 结构层）逐句改写。

无论走哪条路，交付前必须过 `humanize-guide.md` 第四节「润色自检清单」6 条。

### 4. 多平台改写

同一篇初稿，按 `references/style-guide.md` 第三节「多平台改写差异」重写表达层：
- **公众号**：中篇幅、有节奏、小标题分段、情感共鸣收尾。
- **小红书**：短句、emoji、清单体、口语连词、空行多。
- **知乎**：长文、逻辑严密、分点论证、数据来源、承认复杂性。
- **今日头条**：新闻体、倒金字塔、首句给结论、信息密度高。

**改写铁律**：不改事实、不改核心观点，只换表达层（篇幅 / 句式 / 标题 / 平台元素）。
平台专属元素由本规范注入，不依赖模型记忆。

### 5. 索引生成（归档 + 版本管理）

将成品持久化，并维护内容索引。

**调用方式**（确定性，避免每次拼路径）：
```bash
# 归档一篇成文（JSON 来自文件或 stdin）
python scripts/archive_content.py --archive --json article.json
echo '{"title":"...","platform":"小红书","source_topic":"选题slug","body":"..."}' \
  | python scripts/archive_content.py --archive

# 列出已归档（可按平台过滤）
python scripts/archive_content.py --list --platform 公众号

# 重建索引（从成品文件扫描生成，始终与文件一致）
python scripts/archive_content.py --index
```
- 归档路径：`<base>/<平台>/<日期>-<slug>.md`，`base` 默认 `./文案虾/成品/`。
- **版本管理**：同选题同平台重复成文时，版本号递增 v1→v2→…（`source_topic` 或 `slug` 匹配即计为同篇）。
- 索引文件：`<base 上级>/索引.md`，markdown 表格，记录 日期/标题/平台/来源选题/版本/路径。
- 字段规范见脚本内 `_to_markdown`；非法 `platform` 会被校验拒绝。

## 与「选题虾」的衔接

文案虾消费「选题虾」产出的选题卡，并回写状态形成闭环：

1. 「选题虾」产出选题卡（`status=候选`），用户选定后置 `已采纳`。
2. 把选题卡（`title` + `core_points` + `tone` + `emos_hit`）作为文案虾的创作 brief。
3. 文案虾执行 ①~⑤，成品归档到 `文案虾/成品/`。
4. **回写状态**：成文完成后，调用「选题虾」的存储脚本把对应选题卡置为 `已写`：
   ```bash
   python <xuanti-xia路径>/scripts/store_topic.py --update-status <选题slug> 已写
   ```
   （`<xuanti-xia路径>` 通常为 `~/.workbuddy/skills/xuanti-xia`；若跨工作区，按实际路径调整。）
5. 至此「选题 → 成文 → 归档」全链路闭环。

## 使用约束

1. **直接给结果**：输出成品文案本身，不包裹"为您生成如下"等客套前言。
2. **双路不中断**：「内容创作专家」「Humanizer」不可用时，必须回退到本技能内置模板/指南，
   不得因工具缺失而中断成文流程。
3. **多平台不改事实**：改写只换表达层，核心观点与事实零改动。
4. **润色必过检**：无论走 Humanizer 还是兜底，交付前必须过 humanize-guide 自检清单 6 条。
5. **归档确定性**：优先用 `archive_content.py` 归档，避免手写路径导致索引漂移。
6. **风格可扩展**：风格规则见 `style-guide.md` 第一节；用户补充更多条款时直接追加该节，
   下游流程自动继承，不需改脚本。
