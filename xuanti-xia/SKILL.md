# 选题虾 (Topic Selection Shrimp)

## Overview

选题虾是「文案虾」内容生产流水线的**上游环节**，专职为文案创作提供选题输入。
它不直接写文案，而是把三类原始输入（口水稿 / 思路想法 / 热点）转化为结构化、可落库、
可推荐的选题卡，供「文案虾」消费。

结构化模板与字段规范见 `references/topic-schema.md`，确定性存储由
`scripts/store_topic.py` 完成。

---

## 三大核心职责

| 职责 | 输入 | 输出 |
|------|------|------|
| ① 整理口水稿 | 用户口语化、碎片化的草稿/随想 | 结构化主题卡（主主题 + 核心观点 + 隐含需求） |
| ② 挖掘主题 | 用户的思路 / 想法 / 关键词 | 3–5 个主题候选（含差异化角度） |
| ③ 热点分析 | 热点新闻 | 热点 → 选题映射（1–3 个可写角度） |

---

## 五大核心能力（工作流）

### 1. 热点收集（双路兜底）

从热点新闻抓取素材，作为热点分析与主题挖掘的燃料。

**双路策略**（已与用户确认）：
1. **优先**：若 `tencent-news` 连接器可用，调用它抓取腾讯新闻热点榜单 / 分类热点。
2. **兜底**：若 `tencent-news` 未连接或调用失败，使用 `WebSearch` / `WebFetch` 按
   关键词或「今日热点 / 热搜榜」检索全网热点，不受影响地继续。

> 判断连接器是否可用：尝试一次轻量 `tencent-news` 调用；捕获到「工具不存在 / 未授权」
> 等错误时，立即切换 WebSearch 路径，并向用户说明"已用网页检索兜底"。

### 2. 口水稿整理

按 `references/topic-schema.md` 第一节模板执行：
1. 提炼核心观点（3–5 条，去口语冗余）。
2. 提炼隐含需求（受众 / 目的 / 调性）。
3. 归并为主主题 + 2–3 关联子主题。
4. 套用主题卡输出，必要时用 `store_topic.py` 落库。

### 3. 主题挖掘

按 `references/topic-schema.md` 第二节模板执行：
1. **发散**：围绕用户思路找 3–5 个相关方向。
2. **收敛**：对每方向按「EMOS 适配度 + 热点相关度 + 差异化」三维各打 1–5 分。
3. 输出候选列表，标注为什么值得写、目标受众、内容角度、差异化点。

### 4. 选题存储

将选题卡持久化到「文案虾 / 选题库 /」目录。

**调用方式**（确定性，避免每次重写）：
```bash
# 存一个选题（JSON 来自文件或 stdin）
python scripts/store_topic.py --store --json topic.json
echo '{"title":"...","source":"主题挖掘","core_points":["..."],"category":"财经"}' \
  | python scripts/store_topic.py --store

# 列出候选池（选题推荐前先取这一层）
python scripts/store_topic.py --list --status 候选

# 状态流转
python scripts/store_topic.py --update-status <slug> 已采纳
```
- 落库路径：`<base>/<分类>/<日期>-<slug>.md`，`base` 默认 `./文案虾/选题库/`，
  可用 `--base` 覆盖（建议指向「文案虾」项目下的选题库目录）。
- 字段规范见 `references/topic-schema.md` 第五节；非法 `source` / `status` 会被校验拒绝。

### 5. 选题推荐（EMOS 驱动）

按 `references/topic-schema.md` 第六节逻辑执行，输入 = **EMOS 洞察简报 + 用户当前输入**。

**EMOS 四维洞察框架**（用户每次填写，作为推荐匹配键）：
- **E** Emotional 情绪共鸣 — 受众痛点 / 爽点
- **M** Motivation 动机触发 — 什么驱动点击 / 分享 / 行动
- **O** Opinion 观点立场 — 可站队 / 可挑战的边界
- **S** Social 社交货币 — 什么让受众愿意转发塑形

**推荐步骤**：
1. 调 `store_topic.py --list --status 候选` 取候选池。
2. 对每个候选，计算其 `emos_hit` 与本次 EMOS 简报的**命中维度数**。
3. 计算与用户当前输入的相关性（关键词 / 语义重叠）。
4. 排序：`EMOS命中数` 降序 → `相关性` 降序 → `热点加持` 置顶。
5. 输出 Top N，每条附推荐理由（命中了哪些维度、为何契合当前输入）。

> 简化判据：单个选题同时命中 E/M/O/S 中 ≥ 3 维且热点相关度 ≥ 中，即进入「优先推荐」档。

---

## 与「文案虾」的衔接

选题虾只产选题，不写文案。流转建议：
1. 选题虾产出并落库选题卡（`status=候选`）。
2. 用户选定后 `--update-status <slug> 已采纳`。
3. 把选题卡（标题 + 核心观点 + EMOS 命中 + 调性）作为「文案虾」的创作 brief 输入。
4. 文案完稿后 `--update-status <slug> 已写`，闭环选题库。

## 使用约束

1. **热点双路**：不得因 `tencent-news` 不可用而中断；缺失即回退 WebSearch。
2. **EMOS 是用户输入**：EMOS 四维洞察由用户提供，不是自动抓取的数据；缺失时
   基于用户当前输入做基础推荐，并提示"补充 EMOS 洞察可提升推荐精准度"。
3. **不越界写文案**：本技能止于选题，正文创作交由「文案虾」。
4. **落库确定性**：优先用 `store_topic.py` 落库，避免每次手工拼文件路径导致结构漂移。
