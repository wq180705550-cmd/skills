# 选题虾 — 主题与 EMOS 规范

本文件定义选题虾在处理三类输入（口水稿 / 思路想法 / 热点）时使用的结构化模板，
以及 EMOS 四维洞察框架和选题库落库单元「选题卡」的字段规范。SKILL.md 的工作流
直接引用本文件，避免主文档臃肿。

---

## 一、口水稿整理模板（核心职责①）

**输入**：用户口语化、碎片化的"口水稿"（聊天记录、草稿、随想、语音转写等）。

**处理步骤**：
1. 提炼核心观点（3–5 个要点，去掉口语冗余）。
2. 提炼用户隐含需求（目标受众、内容目的、期望调性）。
3. 归并为 1 个主主题 + 2–3 个关联子主题。
4. 套用下方「主题卡」输出结构化结果。

**输出（主题卡精简版）字段**：

| 字段 | 说明 |
|------|------|
| 主主题 | 一句话可传播的主题 |
| 核心观点 | 3–5 条要点列表 |
| 隐含需求 | 受众 / 目的 / 调性 |
| 关联子主题 | 2–3 个可展开方向 |
| 情绪钩子 | 最可能引发共鸣的一句话钩子 |

---

## 二、主题挖掘模板（核心职责②）

**输入**：用户的思路 / 想法（关键词、模糊方向、一个念头）。

**处理步骤**：
1. 发散：围绕思路找 3–5 个相关主题方向。
2. 收敛：按「EMOS 适配度 + 热点相关度 + 差异化」三维打分（各 1–5 分）。
3. 输出主题候选列表，每个含：主题、为什么值得写、目标受众、内容角度、差异化点。

**候选主题条目**：

| 字段 | 说明 |
|------|------|
| 主题 | 候选标题 |
| 为什么值得写 | 价值 / 痛点 / 时机 |
| 目标受众 | 谁会看 |
| 内容角度 | 切入视角（故事 / 清单 / 观点 / 科普） |
| 差异化点 | 与已有同类内容的区别 |

---

## 三、热点分析模板（核心职责③）

**输入**：热点新闻（来自 tencent-news 或 WebSearch 兜底）。

**处理步骤**：
1. 提取热点核心事实（5W1H 压缩为 2–3 句）。
2. 关联用户领域 / 受众。
3. 提炼可写角度：争议点、情绪点、实用点、知识盲区。
4. 输出「热点 → 选题」映射（每个热点给 1–3 个可写选题）。

**热点→选题映射条目**：

| 字段 | 说明 |
|------|------|
| 热点 | 事件简述 |
| 关联领域 | 与用户赛道的关联 |
| 可写角度 | 争议 / 情绪 / 实用 / 盲区（多选） |
| 选题建议 | 1–3 个具体选题 |

## 四、EMOS 四维受众洞察（选题推荐输入）

用户每次提供 EMOS 洞察简报，选题虾据此匹配 / 推荐选题。
EMOS 是**用户填写的洞察输入模板**，不是自动抓取的数据。

- **E — Emotional（情绪共鸣）**：目标受众当前情绪、痛点、爽点是什么。
- **M — Motivation（动机触发）**：什么会驱动受众点击 / 收藏 / 分享 / 行动。
- **O — Opinion（观点立场）**：受众已有的立场、可挑战的立场、可站队的边界。
- **S — Social（社交货币）**：什么内容让受众愿意转发以塑造个人形象。

**匹配规则**：一个选题若同时命中 E / M / O / S 中 ≥ 3 维，且热点相关度 ≥ 中，
则进入「优先推荐」档。命中维度数即推荐强度的主要排序键。

---

## 五、选题卡 schema（选题库存储单元）

每个选题最终落库为一张卡（由 `scripts/store_topic.py` 持久化为 Markdown）。
字段规范：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 自动生成 UUID 短码 |
| slug | string | 文件名用：日期-主题拼音/英文短码 |
| title | string | 选题标题 |
| source | enum | 口水稿整理 \| 主题挖掘 \| 热点分析 |
| main_topic | string | 主主题 |
| core_points | list[string] | 核心观点 |
| audience | string | 目标受众 |
| tone | string | 内容调性 |
| emos_hit | list[enum] | 命中的 EMOS 维度子集 |
| hotspot_link | string? | 关联热点（可选） |
| reason | string | 推荐 / 入选理由 |
| status | enum | 候选 \| 已采纳 \| 已写 |
| created_at | ISO datetime | 创建时间 |

---

## 六、选题推荐逻辑（核心能力⑤）

**输入**：EMOS 洞察 + 用户当前输入 / 想法 +（可选）热点。

**步骤**：
1. 汇总选题库中所有 `status == 候选` 的选题卡。
2. 对每个候选计算 EMOS 命中维度数（与本次 EMOS 简报求交集）。
3. 计算与用户当前输入的相关性（关键词 / 语义重叠）。
4. 排序键：`EMOS命中数` 降序 → `与当前输入相关性` 降序 → `热点加持` 置顶。
5. 输出 Top N 推荐，每条附推荐理由（命中了哪些维度、为何契合当前输入）。

**调用 `scripts/store_topic.py --list --status 候选` 可拿到候选池原始数据。**
