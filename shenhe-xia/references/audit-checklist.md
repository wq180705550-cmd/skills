# 审核虾 · 审核清单与评分量规

对「文案虾」输出的 Markdown 文章做 6 维度质量审核。前 3 维为用户**明确给定**（硬指标，必须达标才能发布）；后 3 维为**正式定义**的语义软指标（默认不阻断发布，仅提示），采用「LLM 语义复核（主）+ 脚本启发式（兜底）」双路，详见文末双路兜底说明。

---

## 维度一：主标题吸引力 · 硬指标

**检查项**
- 能否引起读者兴趣（钩子）
- 是否准确概括核心内容（不标题党、不偏题）
- 是否有悬念或反问

**评分量规（0–100，脚本启发式 + LLM 判断）**
- 长度 8–26 字为黄金区间；<6 或 >30 扣分
- 含悬念/反问词（为什么/如何/怎样/揭秘/背后/真相/其实/竟然/？）→ +吸引力
- 含强吸引词（最/第一/必看/惊呆）→ 略加，但**正文须匹配**，否则准确性扣分
- 标题关键词与正文重合度 < 0.5 → 准确性重扣（偏题/标题党）
- 发布闸门：硬指标，需 ≥ threshold

---

## 维度二：小标题简洁性 · 硬指标

**检查项（用户原话强调）**
- **必须用 `##` 标记，否则看不出来**
- 简洁明了，一眼能看懂
- 逻辑清晰，层次分明

**评分量规（确定性为主）**
- 结构解析：提取全文 Markdown 标题层级
- 主标题 = 唯一一级 `#`；小节标题必须是二级 `##`
- 出现 `###` 深层级 → 提示「建议改用 `##`」
- 检测「伪小标题」：短行（≤20 字）且加粗（`**...**`）但未用 `##` → 提示补标记
- 单条小标题 > 18 字 → 简洁性扣分
- 完全无小标题 → 结构缺失重扣
- 发布闸门：硬指标

---

## 维度三：数据准确性 · 硬指标

**检查项**
- 数据、事实是否准确
- 引用是否有据
- 数字、时间是否正确

**评分量规**
- 自动抽取全文数字、年份、百分比，生成「需人工核查清单」
- flag 异常：年份 > 当前+1（如 2026 出现 2028）、百分比 >100 无上下文、模糊限定词（约/大概/大约）紧邻精确数字
- 正文含数字但零引用标记（`【】` / `[]` / 据 / 来源 / 引用）→ 扣「引用有据」
- 事实真实性需人工或 LLM 复核；脚本只暴露清单与可疑项
- 发布闸门：硬指标

---

## 维度四：事实一致性 · 软指标（LLM 语义复核为主，脚本启发式为兜底）

**检查项**
- 全文论点不自相矛盾（无前后观点冲突）
- 与选题卡 `core_points` 对齐（衔接「选题虾」，传入选题卡时逐条核对）
- 同一实体（公司/指标/时间/人物）的数字前后一致

**评分量规**
- 传入选题卡时：逐条 `core_points` 是否在正文出现（缺失 → 提示）
- 检测同一关键词附近出现不同数字 → 潜在矛盾（兜底：脚本规则）
- **LLM 语义复核（主路径）**：通读全文判定论点逻辑自洽、无隐性矛盾、无偷换概念
- **同步约定**：选题卡 schema 的 `core_points` 字段（由选题虾渲染为 `## 核心观点` + 列表）为上游源，脚本 `_extract_core_points` 解析该 Markdown 格式，随其演进**联动校验**，避免两处漂移（曾因脚本期望 `- **核心观点**:` 而实际为 `## 核心观点` + 列表，导致兜底基线永远抽不到观点）
- 软指标：默认不阻断发布，仅提示

---

## 维度五：AI味检测 · 软指标（衔接「文案虾」；LLM 语义复核为主，脚本启发式为兜底）

**检查项**
- 对照文案虾 `humanize-guide.md` 反模式清单
- 确认润色后无 AI 痕迹

**评分量规**
- 命中 AI 味短语（与「文案虾」`humanize-guide.md` 词汇层对齐：首先/其次/最后/综上所述/值得注意的是/重要的一点/在当今社会/随着…发展/背景下/众所周知/不难看出/显而易见/不可忽视/毋庸置疑/总而言之/总的来说/此外/与此同时/近年来/我们将/让我们/旨在/致力于/赋能/抓手/闭环/不仅…而且/一方面…另一方面…）计数 → 倒扣（兜底：脚本规则，随 `humanize-guide.md` 演进联动校验）
- **LLM 语义复核（主路径）**：判断行文「机器腔」——模板化排比、无信息增量过渡句、过度对仗、空洞词堆砌；比关键词更准确
- **同步约定**：`humanize-guide.md` 词汇层（Layer-1）为上游源，本条短语清单随其增删做**联动校验**，避免两处漂移
- 软指标：AI 味重 → 提示回炉润色（衔接文案虾步骤③润色优化）

---

## 维度六：平台适配性 · 软指标（衔接「文案虾」；LLM 语义复核为主，脚本启发式为兜底）

**检查项**
- 篇幅符合目标平台带宽
- 语气/平台元素匹配

**评分量规（各平台字数区间）**
| 平台 | 推荐字数 | 特殊元素 |
|------|----------|----------|
| 小红书 | 300–800 | 须有 emoji + `#话题标签` |
| 公众号 | 1500–3000 | 适中，段落清晰 |
| 知乎 | 3000–5000 | 重论证深度 |
| 今日头条 | 500–1200 | 短平快 |

- 字数区间 / 平台元素缺失（emoji、`#`话题标签）→ 脚本规则兜底
- **LLM 语义复核（主路径）**：判断语气/元素与平台调性契合度（如小红书生活感、知乎严肃论证、头条短平快）
- **同步约定**：字数区间与「文案虾」`style-guide.md`「多平台改写差异」对齐（`style-guide` 为上游源）；脚本区间随其演进**联动校验**，避免合规文稿被反扣分（曾因 小红书/知乎/头条 下限冲突导致闭环断裂）
- 软指标：仅提示，不阻断发布

---

## 发布闸门（Gate）

- **硬指标** = {主标题吸引力, 小标题简洁性, 数据准确性}，默认阈值 `threshold = 70`
- **软指标** = {事实一致性, AI味检测, 平台适配性}，默认阈值 = `max(40, threshold - 30)`
- `publish = 硬指标全达标 且 软指标全达标`
- 三级结论：
  - ✅ **建议发布**：硬 + 软全达标
  - ⚠️ **需修订**：硬指标未达标（必须先改）
  - ⚠️ **建议润色**：硬达标但软指标偏弱（建议回炉）

> **双路兜底（语义复核双路径）**：脚本 `audit_article.py` 负责确定性结构检查（##标记 / 数字异常 / 字数区间 / AI味短语 / 平台元素），直接出分；对 3 个语义维（事实一致性 / AI味检测 / 平台适配性），**主路径为 LLM 语义复核**（更准确），**兜底为脚本启发式基线**；LLM 不可用 / 报错 / 未接入时回退脚本结果，不中断审核流程，并在报告中标注「语义维为脚本启发式兜底」。
