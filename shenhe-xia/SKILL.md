# 审核虾 (Audit Shrimp)

## 职责

对「文案虾」输出的文章进行多维度质量审核，确保其达到发布标准。本技能位于「选题虾 → 文案虾 → 审核虾」内容生产流水线的末端，是发布前最后一道质检闸门。

## 审核维度（6 个）

> 前 3 维为用户**明确给定**（硬指标，必须达标才能发布）；后 3 维为**正式定义**（软指标，默认不阻断发布，仅提示）。事实一致性/AI味检测/平台适配性定义为语义软指标，采用「LLM 语义复核（主）+ 脚本启发式（兜底）」双路。

### 硬指标（必须达标，默认阈值 70）

1. **主标题吸引力**
   - 是否能引起读者兴趣
   - 是否准确概括核心内容
   - 是否有悬念或反问

2. **小标题简洁性**
   - **必须用 `##` 标记，否则看不出来**（用户原话强调）
   - 简洁明了，一眼能看懂
   - 逻辑清晰，层次分明

3. **数据准确性**
   - 数据、事实是否准确
   - 引用是否有据
   - 数字、时间是否正确

### 语义软指标（默认不阻断发布，仅提示；LLM 语义复核为主、脚本启发式为兜底）

4. **事实一致性** — 全文论点不自相矛盾；传入选题卡时与 `core_points` 对齐；同一实体（公司/指标/时间/人物）数字前后一致。LLM 通读判定逻辑自洽、无隐性矛盾（主路径），脚本做选题卡对齐 + 同实体数字一致性兜底。
5. **AI味检测**（衔接「文案虾」） — 对照「文案虾」`humanize-guide.md` 反模式清单，确认润色后无 AI 痕迹；AI 味重则提示回炉润色（衔接文案虾步骤③）。LLM 判断行文「机器腔」（模板化排比、无信息增量过渡、过度对仗）比关键词更准（主路径），脚本做 AI 味短语命中兜底。**脚本短语清单与 `humanize-guide.md` 词汇层对齐、随其联动校验**，避免两处漂移。
6. **平台适配性**（衔接「文案虾」） — 篇幅/语气/平台元素符合目标平台（小红书需 emoji+话题标签，公众号适中，知乎重论证，头条短平快）。LLM 判断语气/元素与平台调性契合度（主路径），脚本做字数区间 + 平台元素缺失兜底。

> 完整检查项与评分量规见 `references/audit-checklist.md`。

## 工作流

1. **接收文章**：取「文案虾」成品 Markdown（单篇或目录），可选传入 `--topic-card` 选题卡用于事实一致性对齐。
2. **结构解析**：用 `scripts/audit_article.py` 提取标题层级、数字、AI 味短语、平台元素。
3. **六维评分**：脚本输出确定性结构分（小标题##、数据异常）+ 启发式分（标题吸引力、平台适配）+ 软指标分。
4. **发布闸门**：
   - 硬指标全达标 且 软指标全达标 → ✅ 建议发布
   - 硬指标未达标 → ⚠️ 需修订（必须先改）
   - 硬达标但软偏弱 → ⚠️ 建议润色（回炉文案虾步骤③）
5. **写报告**：每篇生成 `<原名>.audit.md` 报告，含维度评分表 + 逐条发现 + 结论。

## 双路兜底说明（语义复核双路径）

审核虾对 6 维采用「**确定性结构检查 + 语义判断**」双路：

- **确定性结构检查（脚本 `audit_article.py`）**：小标题 `##` 标记、数字/年份异常、字数区间、AI 味短语命中、平台元素缺失 —— 纯规则，直接出分，无需 LLM。
- **LLM 语义复核（主路径）**：对需语义理解的 3 个语义维（**事实一致性 / AI味检测 / 平台适配性**），**优先由 LLM 做语义复核**，比关键词/规则更准（如判定论点隐性矛盾、机器腔、平台调性契合度）。
- **兜底（fallback）**：当 LLM 不可用 / 报错 / 未接入时，回退到 `audit_article.py` 的启发式结果作为基线分，**不中断审核流程**；报告中标注「语义维为脚本启发式兜底，建议人工/LLM 复核」。

## 与「文案虾」「选题虾」的衔接

- 输入：消费「文案虾」成品 Markdown；可选「选题虾」选题卡（`core_points`）做事实一致性对齐。
- 闭环：审核虾判定「需修订/建议润色」时，交回「文案虾」步骤③润色优化；判定「建议发布」后，可将对应选题卡置为「已审核/通过」（调用 `xuanti-xia/scripts/store_topic.py --update-status <slug> 已审核`）。

## 使用约束

1. **强制**：小标题必须用 `##` 标记，这是用户明确要求的硬结构规则，审核虾必须检出未标记的小标题。
2. **强制**：数据准确性维度只暴露「需人工核查清单」与可疑项，不替代人工/LLM 事实核查；不得仅凭脚本判文章事实为真。
3. **推荐**：硬指标阈值 `threshold` 默认 70，可按发布标准收紧（如 80）；软指标默认 `max(40, threshold-30)`。
4. **推荐**：AI味检测维度与「文案虾」`humanize-guide.md` 反模式清单保持一致，两技能同步演进。
5. **标注**：本技能后 3 维（事实一致性/AI味检测/平台适配性）现为**正式定义**的语义软指标，采用「LLM 语义复核（主）+ 脚本启发式（兜底）」双路；后续如与「文案虾」`humanize-guide.md` 演进需同步更新 AI味检测清单。
