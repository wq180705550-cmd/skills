# 审核虾 (Audit Shrimp)

## 职责

对「文案虾」输出的文章进行多维度质量审核，确保其达到发布标准。本技能位于「选题虾 → 文案虾 → 审核虾」内容生产流水线的末端，是发布前最后一道质检闸门。

## 审核维度（6 个）

> 前 3 维为用户**明确给定**（硬指标，必须达标才能发布）；后 3 维为**推导补充**（软指标，默认不阻断发布，仅提示），标注【推导】。若你内部对后 3 维有明确定义，告诉我即可替换。

### 硬指标（必须达标，默认阈值 70）

1. **主标题吸引力**
   - 是否能引起读者兴趣
   - 是否准确概括核心内容
   - 是否有悬念或反问

2. **小标题简洁性**
   - **必须用 `##` 标记，否则看不出来**（用户原话强调）
   - 简洁明了，一眼能看懂
   - 逻辑清晰，层次分明

3. **数据准确性**
   - 数据、事实是否准确
   - 引用是否有据
   - 数字、时间是否正确

### 【推导】软指标（默认不阻断发布，仅提示）

4. **【推导】事实一致性** — 全文论点不自相矛盾，与「选题虾」选题卡 `core_points` 对齐，同一实体数字前后一致。
5. **【推导】AI味检测** — 对照「文案虾」`humanize-guide.md` 反模式清单，确认润色后无 AI 痕迹；AI 味重则提示回炉润色（衔接文案虾步骤③）。
6. **【推导】平台适配性** — 篇幅/语气/平台元素符合目标平台（小红书需 emoji+话题标签，公众号适中，知乎重论证，头条短平快）。

> 完整检查项与评分量规见 `references/audit-checklist.md`。

## 工作流

1. **接收文章**：取「文案虾」成品 Markdown（单篇或目录），可选传入 `--topic-card` 选题卡用于事实一致性对齐。
2. **结构解析**：用 `scripts/audit_article.py` 提取标题层级、数字、AI 味短语、平台元素。
3. **六维评分**：脚本输出确定性结构分（小标题##、数据异常）+ 启发式分（标题吸引力、平台适配）+ 软指标分。
4. **发布闸门**：
   - 硬指标全达标 且 软指标全达标 → ✅ 建议发布
   - 硬指标未达标 → ⚠️ 需修订（必须先改）
   - 硬达标但软偏弱 → ⚠️ 建议润色（回炉文案虾步骤③）
5. **写报告**：每篇生成 `<原名>.audit.md` 报告，含维度评分表 + 逐条发现 + 结论。

## 双路兜底说明

脚本给出确定性结构检查 + 启发式评分；对「主标题吸引力准确性」「事实一致性」等需语义判断处：
- **优先**用 LLM 复核（更准确）
- **缺失/报错**时回退到 `audit_article.py` 的启发式结果作为基线，不中断审核流程

## 与「文案虾」「选题虾」的衔接

- 输入：消费「文案虾」成品 Markdown；可选「选题虾」选题卡（`core_points`）做事实一致性对齐。
- 闭环：审核虾判定「需修订/建议润色」时，交回「文案虾」步骤③润色优化；判定「建议发布」后，可将对应选题卡置为「已审核/通过」（调用 `xuanti-xia/scripts/store_topic.py --update-status <slug> 已审核`）。

## 使用约束

1. **强制**：小标题必须用 `##` 标记，这是用户明确要求的硬结构规则，审核虾必须检出未标记的小标题。
2. **强制**：数据准确性维度只暴露「需人工核查清单」与可疑项，不替代人工/LLM 事实核查；不得仅凭脚本判文章事实为真。
3. **推荐**：硬指标阈值 `threshold` 默认 70，可按发布标准收紧（如 80）；软指标默认 `max(40, threshold-30)`。
4. **推荐**：AI味检测维度与「文案虾」`humanize-guide.md` 反模式清单保持一致，两技能同步演进。
5. **标注**：本技能后 3 维（事实一致性/AI味检测/平台适配性）为**推导补充**，非用户原始 spec；用户给出明确定义后据此修订 SKILL.md 与 `audit-checklist.md`。
